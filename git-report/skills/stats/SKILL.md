# 提交节奏分析（Rhythm）

不止"数提交"，而是刻画你/团队的开发节律。纯只读，可作用于全部历史或指定区间。

## 1. 范围
默认全部历史；用户给区间则按 `range` 解析（如"最近 90 天"）。

## 2. 取原始数据
`git log --since="<S>" --until="<U>" --pretty=format:"%an|%ad" --date=iso`
（每条一行：作者 | ISO 时间戳，含时区偏移，便于按时区归到本地小时。）

## 3. 指标（由模型基于上面的行计算，或交给用户本地脚本；无需联网）
- 总提交数
- 涉及作者数与 `shortlog -sn` 交叉验证
- 活跃天数（出现过提交的不同自然日数）
- 最忙星期几（Mon..Sun 计数，按提交者本地日）
- 最忙时段（按小时 0–23 计数；用时间戳里的时区偏移把 UTC 归到本地小时）
- 最长连续提交 streak（按自然日连续天数；缺口即断）
- 人均提交（总/作者数）、最活跃作者及其占比
- 周末 vs 工作日占比（用于"工作生活平衡"类提示，仅基于真实比例，不臆测原因）

## 4. 输出
一段"节奏画像" + 一张小表（指标 | 值），末尾给 1–2 句基于真实数据的观察（如"提交高度集中在周三、四，周末几乎为零"）。
绝不评价个人生活，仅陈述分布事实。

## 5. 纪律
纯只读，不改动任何文件，不调用网络/MCP；只基于真实 git 数据。
